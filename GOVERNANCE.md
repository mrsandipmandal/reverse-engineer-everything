# Governance

## Current model

REE uses a benevolent maintainer model while the project is pre-alpha.

- The maintainer sets technical direction and approves releases.
- Small changes use lazy consensus.
- Architecture changes require an ADR in `docs/adr/`.
- Security-sensitive changes require explicit review and a rollback plan.

## Maintainers

Maintainers are listed in [MAINTAINERS.md](MAINTAINERS.md).

Maintainer responsibilities:

- review contributions;
- keep CI and security checks healthy;
- protect evidence integrity and user safety;
- document decisions;
- mentor contributors.

## Becoming a maintainer

A contributor may be invited to become a maintainer after sustained, high-quality contributions, sound reviews, and demonstrated care for security and evidence quality. The existing maintainer makes the final decision.

## Decision records

Use an ADR for decisions that affect public contracts, evidence semantics, security boundaries, supported platforms, or dependencies with significant impact.

## Code of conduct

Enforcement follows [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md).

## Licensing

Project contributions are accepted under Apache-2.0 with a Developer Certificate of Origin sign-off. No separate contributor license agreement is required.
